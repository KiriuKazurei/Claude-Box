# 框架搭建计划（云电脑推进至接近 beta）

> 决策日：2026-11-11（Asia/Tokyo）  
> 决策者：和零  
> 配套口径：[SCOPE.md](../SCOPE.md) v0.4.0、[identity-presentation.md](./identity-presentation.md)、[architecture-v2-wsl.md](./architecture-v2-wsl.md)

## 目标

在云电脑上把整体架构设计补完、技术细节写清楚，并把代码做到接近 beta；之后再放到真机。真机启用 WSL 仍须和零再次明确批准。本地每个模块完成即 `git commit`，便于回溯；**不** `git push`，除非和零明确要求。

主方案不变：纯 WSL2 + 可见目录，跑 Linux Claude Desktop。WHPX+QEMU 与 `cbox` 仍是效果不好时的后备，本阶段不并列开工。不做「伪装成非虚拟机以绕开检测」。

## 技术选型

| 层 | 选用 | 理由 |
|----|------|------|
| 控件与设置页 | **C++20 + Qt 6** | 和零要求前端优先 Qt；Qt 与 C++ 是一等搭配，可在云电脑 Debian 编译，也面向日后 Win11 宿主控件 |
| 核心策略库 | **C++20**（无 GUI） | 与控件共用同一套清单 / 策略 / 展示合同；命令行与测试不依赖图形界面 |
| 客机启动与 WSL 挂钩 | 现阶段保留 **bash**（及现有少量辅助脚本） | 已有 dry-run 合同（伪装、展示层、smoke）先稳住；由 C++ 核心调用，不在第一批重写 |
| 网关 | 继续复用 **gost + 现有 `ClaudeBox.Gateway`** | 接近 beta 前不重写；控件只负责配置与状态 |
| 不用 C# 做主控件 | — | Qt 不是 C# 的一等方案 |
| 不用 Rust 做主控件 | — | cxx-qt 不如官方 Qt/C++ 稳妥；Rust 仅作为日后网关或采集器的可选替换，本阶段不并列开工 |

云电脑是 Debian，没有 Win11 / WSL。验收以 Linux dry-run、夹具和可编译的控件为准，不假装已经改写活的 `/sys/class/dmi`，也不在和零电脑上启用 WSL。

## 模块与优先级

按依赖顺序逐个完成。每个模块结束时在云电脑仓库本地提交（可回溯），并留下可在本机跑的测试或自检。

| 优先级 | 模块 | 要做的事 | 云电脑验收（接近 beta 前） |
|--------|------|----------|------------------------------|
| **P0** | 方案与计划落盘 | 本文件 + SCOPE / 架构 / 身份展示口径 | 文档已本地提交 |
| **P1** | 身份策略引擎 | C++ 库：字段清单、每字段 `expose` / `hide` / `override`、默认策略、apply / verify | 夹具测试全绿；默认隐藏硬件编码；按策略覆盖后，指定字段可进入展示层 |
| **P2** | 采集器 | 部署后采集电脑有关信息，写入盒子内**原始清单**（不自动交给 Claude） | 夹具可采集；原始清单与展示层分离；真实编码只出现在原始清单 |
| **P3** | 展示层接线 | 按用户策略生成展示层；包裹或替换现有 `apply-host-identity` | 既有 smoke 仍过；新增「隐藏 / 修改后展示 / 选择展示」用例 |
| **P4** | 控件壳（C++/Qt） | 设置页列出采集结果；用户选择原样展示、隐藏、或修改后展示并保存 | 无头测试通过；云电脑可编译并打开设置页（无真机也可点选夹具数据） |
| **P5** | 运行时与目录隔离 | 发行版生命周期、`visible_dirs`、拒绝整挂宿主 `C:`；控件接线 | dry-run 挂载计划测试；配置拒绝 `C:` |
| **P6** | 唯一网关 | 上游（含 Clash）、JSONL、blocklist；控件显示状态 | 既有 gateway smoke 仍过；控件可读写上游与日志路径 |
| **P7** | 时区 / 语言伪装 | 沿用 `apply-spoof`；设置页展示的是**盒子伪装值** | Intl 探针仍为配置中的假时区 / 语言；不把宿主真实时区当作默认可展示字段 |
| **P8** | 伴生指纹浏览器 | 将 W6 从桩接到可用实现 | 授权 URL 不回退宿主默认浏览器；出网仍经网关 |
| **P9** | 身份保险库 | 将 W7 从桩接到可用实现 | 归档 / 切换 / 回滚只动盒子目录 |
| **P10** | 启停 Desktop + 可选 IP 杀进程 | 控件启停；`kill_on_local_ip_change` 默认关 | dry-run 启停桩通过；不在云电脑假装已启动真机 Desktop |
| **P11** | 集成，做到接近 beta | 全链路 dry-run 验收清单、文档与行为对齐 | 上述模块测试全绿；缺真机的项逐条标明，不写成功 |

**P11 之后**才考虑真机 W1（启用 WSL、接真实 Desktop）。那一步必须和零再点头。

## 与现有代码的关系

- `src/wsl-box/` 的 bash / PowerShell dry-run **保持可跑、测试保持全绿**。P3 已接线：`apply-host-identity.sh` / `verify-host-identity.sh` 调用 C++ `claudebox-identity` 生成并校验展示层。
- `hide_identifiers: true` 仍是过渡约束（设为 false 会失败，避免整份原始清单被放开）。按字段的 `expose` / `hide` / `override` 通过 `CLAUDE_BOX_IDENTITY_POLICY` 或 `var/host-identity.policy.yaml` 生效。
- P1 起新增 `src/claudebox/`（C++ 核心）与 `src/claudebox-ui/`（Qt 设置页，P4）。旧的 `ClaudeBox.Control`（WinForms / Hyper-V）只作参考，不再作为主控件方向。
- 默认策略不变：厂商 / 型号可原样展示，硬件编码默认隐藏；用户策略可以改为展示或修改后展示。设置页（P4）已落地：`src/claudebox-ui/` 可在云电脑用夹具打开，编辑全部 `wsl-box.yaml` 配置段与每字段身份策略。

## 工作约定

- 只在云电脑仓库提交；不 push，不改和零的 Win11，不启用真机 WSL。
- 一个模块一次（或一组紧密相关的）本地提交，提交说明写清模块编号。
- 不把「隐藏 WSL / 虚拟机特征」或「绕开平台检测」写进模块范围。
